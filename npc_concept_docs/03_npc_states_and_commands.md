# 03. Состояния NPC и команды игрока

## Общие правила

NPC управляется простой конечной машиной состояний.

Состояние определяет текущий режим поведения, но выбор цели во всех обычных состояниях строится через оценку точек пространства.

Игрок не отключает самостоятельную логику NPC. Команды игрока повышают приоритет соответствующих точек.

## Список состояний

```text
Idle
MoveToPoint
FollowPlayer
AssistedByPlayer
Chaotic
Incapacitated
Evacuated
```

## `Idle`

NPC находится на месте и периодически пересчитывает желательность доступных точек.

В `Idle` NPC:

- может подавать кашель;
- оценивает окружающие точки;
- может остаться на месте;
- может перейти в `MoveToPoint`, если найдена более желательная точка;
- может перейти в `Chaotic`, если паника достигла критического порога;
- может перейти в `Incapacitated`, если ущерб достиг критического порога.

## `MoveToPoint`

NPC движется к выбранной точке через `NavMeshAgent`.

Переход в `MoveToPoint` происходит, когда в состоянии `Idle` или после пересчёта решения найдена более желательная точка.

В `MoveToPoint` NPC:

- движется к `CurrentTargetPosition`;
- периодически пересчитывает цель;
- может сменить цель, если новая точка лучше текущей на `SwitchTargetThreshold`;
- может вернуться в `Idle`, если достиг цели;
- может перейти в `Chaotic`;
- может перейти в `Incapacitated`.

## `FollowPlayer`


Команда означает, что NPC должен стараться держаться рядом с игроком.

Реализация команды:

- точки рядом с видимым игроком получают повышенный приоритет;
- величина бонуса зависит от `TrustToRescuer`;
- NPC не обязан идти к игроку, если суммарная оценка других точек выше;
- если NPC впадает в панику, команда перестаёт выполняться;
- если игрок удаляется дальше `FollowDistance`, NPC возвращается к самостоятельной логике.

Условие прекращения следования:

```text
if DistanceToPlayer > MaxFollowDistance:
    clear FollowPlayer command
    State = Idle
```

NPC не ускоряется для догоняния игрока.

## `AssistedByPlayer`

`AssistedByPlayer` не является командой.

Состояние включается, когда игрок физически касается NPC и удерживает его.

В этом состоянии:

- NPC продолжает иметь собственное желательное направление;
- игрок может вести NPC;
- скорость игрока снижается от веса, мобильности и сопротивления NPC;
- вибрация контроллера зависит от сопротивления;
- если игрок отходит от NPC дальше допустимой дистанции удержания, взаимодействие разрывается.

После разрыва взаимодействия NPC возвращается к обычной логике.

## `Chaotic`

Состояние запускается при достижении критического уровня паники.

```text
if CurrentPanic >= PanicCriticalThreshold:
    State = Chaotic
```

В состоянии `Chaotic` NPC:

- игнорирует команды игрока;
- не учитывает `SpatialOrientation`;
- не подаёт кашель;
- выбирает случайную незаблокированную точку;
- движется к выбранной точке через NavMeshAgent;
- остаётся в состоянии фиксированное время.

Длительность:

```text
ChaoticDuration = MinChaoticDuration + ChaoticBehaviorDuration * MaxExtraChaoticDuration
```

После завершения хаотичного состояния NPC возвращается к обычной логике:

```text
State = Idle
```

## `Incapacitated`

Состояние запускается при достижении критического ущерба.

```text
if CurrentDamage >= CriticalDamageThreshold:
    State = Incapacitated
```

В состоянии `Incapacitated` NPC:

- находится в лежачем состоянии;
- не двигается самостоятельно;
- не выполняет команды;
- не подаёт кашель;
- может быть эвакуирован только перетаскиванием.

Отдельное состояние `CarriedByPlayer` не используется.

Если игрок перетаскивает недееспособного NPC, состояние NPC остаётся `Incapacitated`.

## `Evacuated`

Состояние устанавливается, когда NPC достиг зоны эвакуации.

NPC может теоретически достичь выхода самостоятельно, если маршрут не заблокирован уровнем.

После перехода в `Evacuated` NPC больше не участвует в выборе точек, угрозах и командах.

## Команды игрока

Команды игрока:

```text
FollowPlayer
Stop
GoThere
LowMovement
```

Команды проходят через задержку реакции:

```text
ReactionDelay = MinReactionDelay + CommandReactionDelay * MaxExtraReactionDelay
```

Команды не имеют накопительного эффекта при повторной подаче.

NPC может не выполнить команду, если после суммарной оценки другая точка остаётся более желательной.

## `FollowPlayer`



После получения команды:

- точки рядом с игроком получают бонус;
- NPC стремится приблизиться к игроку;
- если игрок продолжает двигаться, бонус пересчитывается относительно новой позиции игрока;
- выполнение зависит от доверия к спасателю и опасности окружающих точек.

Бонус:

```text
FollowScore = RescuerProximity * TrustToRescuer * RescuerWeight + CommandWeight
```

Команда активна, пока игрок находится в пределах `FollowDistance`.

## `Stop`

Команда повышает приоритет текущей позиции NPC.

```text
CurrentPositionBonus = StayPointBonus + StopCommandBonus * TrustToRescuer
```

NPC может покинуть место, если другая точка становится значительно более желательной.

## `GoThere`

Команда задаёт целевую область через указание VR-контроллером.

Игрок указывает позицию лучом.

Система находит ближайшую точку на NavMesh и использует её как `CommandTargetPosition`.

Точки рядом с целевой позицией получают бонус:

```text
GoThereScore = CommandTargetProximity * CommandWeight * TrustToRescuer
```

NPC будет стремиться идти туда только если итоговая оценка таких точек становится выше альтернатив.

## `LowMovement`

Команда включает или отключает низкое движение.

`LowMovement` не является отдельным состоянием.

Флаг:

```text
IsLowMovement = true/false
```

Низкое движение:

- снижает скорость;
- снижает ущерб от дыма;
- снижает рост паники от дыма.

Механика низкого движения реализуется в последнюю очередь MVP.

## Приоритеты переходов

Переходы с высоким приоритетом:

```text
CurrentDamage >= CriticalDamageThreshold -> Incapacitated
CurrentPanic >= PanicCriticalThreshold -> Chaotic
ReachedEvacuationZone -> Evacuated
```

Эти переходы важнее команд игрока.

## Несколько NPC

В сцене может быть несколько NPC.

NPC не используют групповое поведение.

NPC учитывают друг друга только для избежания столкновений через стандартные средства NavMeshAgent.

Команды игрока применяются ко всем NPC в радиусе действия команды.
